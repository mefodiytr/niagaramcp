## Surprises during implementation

### What went exactly as recon predicted

- **Knowledge store integration into `BMcpPlatformService`** (recon §6.2) — exactly the pattern. Three new properties, one static volatile field, one accessor. ~80 LOC.
- **Tool registration pattern unchanged from v0.1/v0.2** — registered all 23 in the same `serviceStarted()` block; no new registration mechanism needed.
- **MCP dispatch extension is mechanical** — 5 new `if` branches in `McpProtocol.handle()` mirror the `tools/list` / `tools/call` pattern.
- **Capability advertisement bump is one-line** — `caps.put("resources", new JSONObject())` etc.
- **`Sys.getNiagaraUserHome()` works** without new permissions (recon §3.1, ADR-0002 §6).
- **Atomic file write via `Files.move(ATOMIC_MOVE)`** works on NTFS as expected (recon §3.3).

### Three recon predictions wrong at compile

These hit at commits 9–10 (history/alarm work) and were exactly the kind of failure the recon flagged in §1.9 and §2.8 as TBD:

1. **`HistorySpaceConnection.timeQuery(...)` returns `BITable<BHistoryRecord>`, NOT `HistoryCursor`** — recon §1.3 mis-described it. Fix: chain `tbl.cursor()` to get a `TableCursor`. Documented in commit 9 message.

2. **`BHistoryService.getHistoryDb()` does not exist** — recon §1.2 sketched it. Actual method is `getDatabase()` returning `BISpace` (cast to `BHistorySpace`). Fix in commit 9.

3. **`BAlarmRecord.getSource()` returns `BOrdList` directly, NOT a `BAlarmSource` wrapper** — recon §2.5 had it as `BAlarmSource` with `.getOrd()` / `.getName()` accessors. None of those exist on the actual return type. Fix: `.toString()` for the ord, `getAlarmFacet(SOURCE_NAME)` for the name. Documented in commit 10 message.

These fixes added ~20 LOC over the recon estimate.

### Niagara gradle deps NOT transitive

Recon §6.7 hoped `:history-rt` and `:alarm-rt` might come in transitively via `:control-rt`. They don't. Adding both to `niagaramcp-rt.gradle.kts` was needed. Plus `:bql-rt` because alarm classes reference `javax.baja.bql.{Queryable, BIRelational}` at compile time. Three lines of gradle change in commits 9 and 10.

### YAML LOC overrun (commit 2a, 44 % over)

The YAML emitter+reader+exception came in at 649 LOC, vs the 450 estimate / 500 hard cap from the brief. Pure code (excluding Apache headers + javadoc) is closer to ~470, marginally over. The brief's "stop and switch to JSON-only" applied only when edge cases weren't finished — they were. Commit message documented the overrun fully; not switching to JSON-only because functionality is complete.

### Class import boilerplate

`BMcpPlatformService.java` grew from 5 tool imports to ~30 imports + 4 registry imports + 13 prompt/resource imports = 47 imports just for the wiring. Considered a `static{}` block with reflection but Java 8 + bundled-jar simplicity won.
