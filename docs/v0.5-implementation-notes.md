## Surprises during implementation

### `Sys.getCurrentContext` / `BUserService.runAs` don't exist

The early design pass assumed `gateway.run(BUser, ThrowingSupplier<T>)`
with a thread-local Context. Recon revealed Niagara has no
{`Sys.makeContext`, `BUserService.runAs`, `BLocalSession.makeContext`}
— every mutating Baja call (`add`, `set`, `remove`, `rename`,
`invoke`) takes Context as an explicit parameter. So the gateway
shape changed to `run(BUser, OpDesc, args, sessionId, ContextAwareWork<T>)`
where the work lambda receives `cx` and threads it to each call site
itself. Documented in commit 6 and the recon report from the design
pass.

### `BUser implements Context, Principal`

A BUser instance can be passed directly as a `Context` parameter
without wrapping. We still wrap with `new BasicContext(user)` for
proper default facets, but the chain is shorter than expected.

### `BAuditService` does not exist in public API

The early plan was "BAuditService.add() primary, JSONL detail".
Recon found no `javax.baja.BAuditService`. Audit infrastructure is
just two interfaces: `Auditor.audit(AuditEvent)` and
`SecurityAuditor.audit(SecurityAuditEvent)`. The concrete service
that ships with Niagara is
`com.tridium.history.audit.BAuditHistoryService` — a
`com.tridium.*` non-public class. Plus `history-rt.jar` is not on
every station (lightweight JACE installs ship without it).

Result: roles flipped. **JSONL is now THE primary audit** (always
on, full record). `BAuditHistoryServiceAdapter` is best-effort
secondary, **reflection-only** to avoid hard `NoClassDefFoundError`
on edge stations. Method handle cached at install time; per-call
overhead ≈ 0. Field mapping is lossy because `AuditEvent` has only 6
fixed fields (operation/target/slotName/oldValue/value/userName) —
args / durationMs / sessionId / errorMessage live in JSONL only.

### `PermissionException` carries no rich payload

Only a String message — no `getUser()`, `getPermission()`, `getOrd()`.
The wrapper rebuilds `error.data{user, ord, operation, tool}` from
the call-site `OpDesc` (the reason OpDesc exists as a separate
parameter rather than being derivable from the exception).

### TagDictionary auto-bootstrap scoped down

Commit 4 was framed as "auto-bootstrap" the `mcp:` namespace via
programmatic registration. Recon revealed
`javax.baja.tagdictionary.BTagDictionary` requires a populated
`BTagInfoList` (tag definitions + group definitions + valid-entity
predicates) to register meaningfully — that's a self-contained
domain ~hundred-LOC feature on its own.

Decision: **ship constants + a reflection check that asks "is the
dictionary already there?"**. On miss, log once pointing the
operator to the manual fallback (drop a `BTagDictionaryFile` under
`Services/TagDictionaryService`). Tag write/read works without
registration; only the Workbench TagBrowser entry is missing. Honest
"best-effort" without overclaiming.

Documented in commit 4 message and in CHANGELOG "Known follow-ups".

### Python smoke client had `--skip-v041` already; v0.5 follows the same opt-in shape

Existing `--skip-v04 / --skip-v041` toggle pattern carried over to
`--skip-v05`. v0.5 adds two tunable args (`--smoke-user`,
`--smoke-parent`) so an operator can re-target the test BUser /
parent ord without editing the script.

### Auto-promote `structuredContent` is a backward-compat freebie

Q11 in the design pass was "new tools emit both `text + structuredContent`,
existing unchanged". Implementation shortcut: McpProtocol.callTool()
checks if the returned text starts with `'{'` and parses as JSONObject
— if so, ALSO emits as `result.structuredContent`. Affects ALL tools
whose payloads are JSON-shaped (most of the 36 in v0.4.1). Pure
addition; old MCP clients keep reading `content[0].text`. Backfill
that the v0.6 plan-item asked for happened automatically.
