## Items

### a — `BValueCoercer` (commit `81a4c77`)

`SetSlotTool` and `InvokeActionTool` each carried a near-identical private
copy of the JSON↔BSimple coercion. Pulled into one package-private helper
`com.niagaramcp.server.tools.BValueCoercer`:

| method | what |
|---|---|
| `coerce(BValue template, Object raw)` | BValue of `template`'s BSimple type (BString/BBoolean/BInteger/BLong/BFloat/BDouble), else `UnsupportedTypeException(hint)`; bad numeric/boolean → `NumberFormatException`. |
| `toJsonScalar(BValue)` | String/Boolean/Integer/Long/Float/Double, else `v.toString()`, null→null. |
| `typeSpec(BValue)` | `"module:Type"` or `"null"`. |
| `isSupported(BValue)` | true iff one of the six BSimple primitives. |

Both tools delegate; their private coercion + the two bespoke exception
classes are deleted, and now-unused imports trimmed. No behavior change
(smoke 27/28 unaffected).

### d — `clearSlot` tool (commit `65aab8a`)

New `category: "write"` tool, `requiresUserContext=true`, `MUTATION`.
Args `{ord, slotName}`. Resolves the ord to a BComponent (via `Ords.resolve`,
so absolute or relative `slot:/...`), finds the Property slot, and
`target.set(prop, prop.getDefaultValue(), cx)` under the user-Context
gateway. Works for any Property slot type (BSimple or complex — no JSON
value to coerce). Action/Topic slots aren't Properties → `getProperty`
returns null → `-32006`. A read-only slot rejecting the write → `-32603`
with Niagara's message. Result `{ord, slotName, previousValue, defaultValue,
type, changed}` where `changed = !prop.isEquivalentToDefaultValue(prev)`.
Registered in `BMcpPlatformService` → `tools/list` 45 → 46.

### e — `unlinkSlots` `{sinkOrd, linkName}` form (commit `ee55fb2`)

`unlinkSlots` now takes EITHER `{linkOrd}` (as before) OR `{sinkOrd,
linkName}` — the latter mirrors how `linkSlots` returns its result and how
a link reads in the nav tree (a named slot on the sink). Validation
"`linkOrd` XOR (`sinkOrd` & `linkName`)" is in `call()` (JSON Schema can't
express it). `{sinkOrd,linkName}` path: resolve `sinkOrd` → BComponent →
`sink.get(linkName)`; missing slot → `-32006`, non-`BLink` slot → `-32602`.

**Bug fixed alongside:** a `BLink` is a `BRelation`, not a `BComponent`
(`BRelation` is a `BComplex` but lacks `getSlotPath()`). The post-smoke
`cadf51c` change in `linkSlots` had an `instanceof BComponent` branch for
the mounted link that *always* fell through to
`getSlotPathOrd().toString()` — a relative `slot:/...`. Both tools now
build the link's display ord from the sink's fully-qualified ord + the
link slot name → `"station:|slot:/.../FooLink"`.

### b — `addExtension` applicability pre-check (commit `c4dfc0f`)

Before the add, `addExtension` runs Niagara's own predicates —
`parent.isChildLegal(ext)` and `ext.isParentLegal(parent)` (the pair
`add()`'s internal `checkAdd` consults for constrained components). If
either returns false the add is refused with `-32015
ERR_EXTENSION_NOT_APPLICABLE` and `data{parentOrd, parentType,
extensionType, reason}`, instead of letting Niagara throw at `add()` time
(generic `-32603`). The check runs only when the extension type
instantiates to a `BComponent` (always, for real extensions). Both
predicates default to `return true` (verified in bytecode), so
unconstrained parents (folders) are unaffected. This activates the
`-32015` code declared-but-dormant since v0.5.1.

## Recon notes (baja 4.15.3.28)

- `BComponent.getSlotPathOrd()` is literally `BOrd.make(getSlotPath())`
  → its `toString()` is the *relative* `slot:/...` body, same as
  `getSlotPath().toString()`. The canonical, resolvable form is
  `"station:|" + getSlotPath()` (`Ords.stationOrd`).
- `BLink extends BRelation`; `BRelation extends BComplex` (has
  `getParent`/`getPropertyInParent`), but **not** `BComponent` — no
  `getSlotPath()`. `BLink.getSourceComponent()`/`getTargetComponent()`
  *do* return `BComponent`.
- `BComponent.isChildLegal(BComponent)` / `isParentLegal(BComponent)` —
  default impl `return true`; constrained subclasses override. `add()`
  calls `checkAdd(...)` which consults these.
- `Property.getDefaultValue()` returns the slot's declared default;
  `Property.isEquivalentToDefaultValue(BValue)` is the cheap "is this
  already default?" check.
