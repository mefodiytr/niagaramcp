## Surprises during implementation

### What went exactly as brief predicted

- Commit 1 (transport toggles): 2 properties, servlet checks,
  initialize.transports advertisement, -32009 error code — all
  fit cleanly. ~85 LOC, brief estimated 70.
- Commit 5 (getDiagnosticDump): clean reuse of existing accessors.
  ~125 LOC, brief estimated 80 (overran ~55%, but each section
  needed defensive null-handling that wasn't in the sketch).
- Commit 6 (translation): JSON library javadoc was straightforward.
  No code change, no risk.

### Brief vs reality divergences (be honest)

- **Commit 4 jar savings vastly underdelivered.** Brief expected
  8-12 KB savings from helper dedup; actual is roughly **+82
  bytes net** (after accounting for ToolSchemaHelpers class
  itself). Java compile-time constant inlining means
  `static final String` references DON'T dedupe — each call site
  inlines the literal. Converting EMPTY_SCHEMA to a method
  (`emptySchema()`) recovered some bytes but the helper class
  itself costs ~1.5 KB. Brief allowed "if savings < 5 KB,
  accept and continue" — accepting.
- **Commit 6 (translation) scope smaller than brief implied.**
  Brief listed specific files for translation but said "translate
  Russian COMMENTS"; tool `description()` returns are method
  return values, not comments, so I left them in Russian. This is
  a scope decision documented in the commit message — translating
  user-facing strings would have changed AI client behavior.
  Deferred to v0.5 i18n work.
- **Total LOC delta is NEGATIVE** because commit 3 removed more
  than the rest added. Brief estimated "~400 LOC total" — actual
  +805 / −2 423 = -1 618. This is GOOD: jar shrunk and codebase
  shrunk too.
- **`getDiagnosticDump` per-transport session split deferred.**
  Brief showed `sessions: {sse: [...], streamable: [...]}` with
  per-transport arrays. McpSessions doesn't expose typed iteration
  in v0.3.1, only an aggregate count. Implemented as
  `sessions: {totalActiveCount: N}` — degraded gracefully.
  Per-transport iteration deferred to v0.5 (would require a small
  McpSessions API change).
- **Reading `serverInfo.version`** — was hardcoded `"1.0.0"` since
  v0.1.0, never noticed before. Now sourced from
  `GetServerInfoTool.NIAGARAMCP_VERSION = "0.4.0"`. Considered:
  is this a "Changed" or a "Fixed"? Marked as "Changed" in
  CHANGELOG since callers may have hardcoded "1.0.0" expectations
  in their integration code (unlikely but possible).

### Niagara API surprises

None — all v0.4 changes use existing Niagara APIs from v0.3.x. No
new gradle deps, no new permissions. Most work is in `tools/`,
`json/`, and one `McpServlet` extension.

## Things deferred (with rationale)

| Item | Why deferred |
|---|---|
| Runtime-mutable `sseEnabled` / `streamableEnabled` (without restart) | Same precedent as v0.3.1 `disabledTools`. Niagara property `changed()` callbacks could implement this in v0.5. |
| Per-transport session arrays in `getDiagnosticDump` | Requires McpSessions to expose typed iteration. Aggregate count works for monitoring; detail is for forensics. |
| Translate user-facing `description()` strings to English | Need proper i18n message bundle so Russian-speaking deployments can keep RU descriptions. v0.5 work item. |
| Further JSON library shading (rename to `com.niagaramcp.embedded.json`) | Avoids classloader conflicts on MCS stations that ship their own `org.json` family. v0.5 if real conflict observed. |
| BPasswordPassword for apiToken, BAuditService, RBAC — see CHANGELOG Planned section | Bigger v0.5 features. |
| Spy view, web admin UI | Brief explicitly excluded; needs separate Niagara recon. |
