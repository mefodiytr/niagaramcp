## Branch strategy

Create `v0.3.0-semantic-layer` off `main` immediately. Every commit
goes there. Branch is **not merged** at the end of this work — left
unmerged for human review, identical to the v0.2.0 pattern.

## Hard constraints

- **Java 8 baseline.** No `var`, no lambdas-in-interfaces, no switch
  expressions, no records, no `Optional` chaining without null
  guards. Read like Java 7.
- **No new runtime threads.** No `ExecutorService`, no
  `Thread.start()`, no `ScheduledExecutorService`. The lazy-eviction
  pattern from v0.2.0 (`StreamableSession.acquireStreamable`) is the
  precedent for any time-based behaviour.
- **No new third-party dependencies.** Specifically: do not add
  snake-yaml. The YAML emitter+reader must be hand-written per
  recon §4.4 (~330 LOC budget, hard cap 500 LOC).
- **Backward compatibility absolute.** Every v0.2.0 endpoint must
  continue to work bit-for-bit:
  - SSE flow: `GET /sse` + `POST /messages?sessionId=…`
  - Streamable HTTP flow: `POST /mcp`, `GET /mcp`, `DELETE /mcp`
  - All five existing tools: echo, listChildren, readPoint,
    writePoint, bqlQuery
  - Bearer auth on every endpoint
  - `mcpSessionIdleTimeoutSec` lazy idle eviction
- **Each commit builds green in isolation.** Verify with
  `./gradlew :niagaramcp-rt:assemble --configure-on-demand` after
  each commit. If a commit doesn't build, fix it before moving on —
  no "I'll fix this in the next commit" patterns.
- **module-permissions.xml not edited** unless recon §3.4 turns out
  wrong at compile time (i.e., a `SecurityException` blocks file
  I/O during a smoke run). Recon explicitly stated no new
  permissions are needed.
- **Don't merge.** Branch `v0.3.0-semantic-layer` stays unmerged.
  No `git merge`, no `git tag`, no `git push origin main`.

## Confirmed decisions (from §11 of recon)

All eight open decisions are accepted per Claude Code's
recommendations:

1. **`knowledgeFilePath` default = `""`** with accessor returning
   `${niagaraUserHome}/niagaramcp/knowledge.yaml` when empty. Same
   pattern as v0.2.0's `apiToken`.
2. **Sample knowledge.yaml in jar** (`resources/sample-knowledge.yaml`),
   exposed via `resources/list` as `niagara://samples/standard-types`.
   Operator can opt-in via `importKnowledge` tool.
3. **Resources require Bearer auth.** Same gate as Tools.
4. **YAML default on first write.** Dual-format read (YAML or JSON
   on disk both accepted).
5. **7 prompts hard-coded in jar.** `prompts:` section in knowledge
   schema is reserved for v0.4+ but not implemented now.
6. **Aliases case-insensitive** via `String.toLowerCase(Locale.ROOT)`
   on both sides of comparison.
7. **`reloadKnowledge` tool** for refresh after manual file edit.
   No file watcher. No new threads.
8. **Property naming without `mcp` prefix.** `knowledgeFilePath`,
   `knowledgeAutoBackup`, `knowledgeBackupCount`. The `knowledge*`
   namespace is self-disambiguating.

These should be formalised in ADR-0002 at commit 1.

### Commit 2a — `feat: YAML reader/writer (hand-written, ~330 LOC)`

Files (all new under
`niagaramcp-rt/src/com/niagaramcp/server/yaml/`):

- `YamlReader.java` — accepts both YAML and JSON syntax (dual
  format read per §4.4). Returns `Object` tree of
  Map<String,Object>/List<Object>/String/Long/Double/Boolean/null.
- `YamlWriter.java` — writes YAML output with 2-space indent,
  block style only, double-quoted strings only when necessary
  (per §4.3 quote rules).
- `YamlException.java` — checked exception with line/column
  pointer for error messages.
- (optional) `AbstractEmitter.java` if it cleans separation
  between Reader and Writer.

Subset of YAML 1.2 to support per recon §4.2:
- nested maps and lists (block style)
- strings (plain, single-quoted, double-quoted)
- ints, doubles, booleans (true/false), nulls
- comments (`#`) — skip on read, don't emit on write
- NOT supported: anchors, references, multi-line block scalars
  (`|`/`>`), custom tags, flow style for output (read should
  tolerate flow-style input from JSON)

Edge cases handled per recon §4.3:
- strings with leading whitespace → quote
- strings that look like numbers → quote
- strings with `:` or `#` mid-token → quote
- unicode strings → utf-8 encoded, no escaping in output
- empty string vs null distinction preserved on roundtrip

Validation: roundtrip test data in javadoc comments — author N
sample fixtures and prove `read(write(x)) == x` for canonical
schema shapes by tracing through the code mentally. No JUnit yet
(test infra is a separate concern).

Estimate: ~450 LOC. **Hard cap 500 LOC.** If you cross 500
without finishing edge cases, stop and switch to recon §4.7
fallback (JSON-only via embedded `com.niagaramcp.json`). Document
the switch in the commit message.

### Commit 2b — `feat: KnowledgeStore + KnowledgeModel`

Files (all new):

- `KnowledgeModel.java` — root holder. Fields: `schema_version`
  (int), `spaces`, `equipment_types`, `equipment`, `points`.
- `Space.java`, `EquipmentType.java`, `Equipment.java`,
  `Point.java` — immutable value classes. Java 8 means no
  `record`; use private final fields + getters + builder pattern
  for ones with many fields. Each has Javadoc explaining the
  schema link to `02-format.md`.
- `KnowledgeStore.java` — orchestrator:
  - `load(File path)` — reads file (or returns empty if absent),
    populates in-memory Model. Uses `YamlReader` from 2a.
  - `save(File path)` — atomic write per recon §3.5 (write to
    `.tmp`, `Files.move(..., ATOMIC_MOVE)`).
  - `lock()` — returns AutoCloseable monitor (synchronized
    block under the hood). Single-writer guard.
  - `getModel()` — read-only view.
  - `reload()` — invalidates cache, calls `load` again.
  - Backup rotation per `04-roadmap.md` and §3.6 of recon —
    keep last N backups (N from `knowledgeBackupCount` property,
    default 5).
- `KnowledgeException.java` — wraps schema violations, missing
  required fields, version mismatches.

Schema validation per `02-format.md`: required fields present,
no orphan equipment (every equipment.space references a defined
space), no duplicate ids, schema_version ≥ 1.

Resource access from `niagaramcp-rt/src/resources/` (new
directory): `sample-knowledge.yaml` bundled in jar. Loadable
via classloader for the `niagara://samples/standard-types`
resource (commit 11). Author the sample now with ~5 generic
equipment types (AHU, Chiller, Pump, RTU, FCU) and example
spaces — see `02-format.md` §3 for format.

Estimate: ~650 LOC Java + ~80 LOC sample YAML = ~730 LOC.
