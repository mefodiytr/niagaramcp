## Surprises during implementation

### `BComplex.getPropertyInParent()` is the right slot-resolver
Initial draft of `removeComponent` used
`parent.getProperty(target.getSlot(target))` which doesn't compose.
Recon caught it before commit; corrected to `target.getPropertyInParent()`.
Same fix applied later in `unlinkSlots`.

### `BStation` exposes both `save()` and `doSave(Context)`
`save()` is the no-arg convenience method (default cx → service
identity). `doSave(Context)` is the impl that subclasses override;
calling it directly with our user-Context propagates user identity
properly. Used the latter in `commitStation` so the audit story
holds. Niagara convention: `xxx()` ↔ `doXxx(Context)`.

### `BLink` is the link target's child slot
The link-data structure is stored as a child slot on the SINK
component (= where data flows TO), not on the source. So
`sink.getLinks()` returns inbound links to that sink. For
`removeComponent`'s safety check, this directly answers
"is anyone reading from me?" without a station walk.

### `LinkCheck` API found cleanly
`BComponent.checkLink(source, sourceSlot, sinkSlot, cx)` returns a
`LinkCheck` with `isValid()` + `getInvalidReason()`. Niagara owns
the type-compatibility predicate, we just surface the reason in
`-32016 ERR_LINK_TYPE_MISMATCH` data.

### Auto-pick converter (Q6) deferred
Walking the converter registry isn't a stable public API. v0.5.1
ships hard "convert: false" semantics (refuse on type mismatch).
v0.5.2 will add explicit `converterType` arg + lookup of
named BTypeConverter — design Q6 already locked.

### Smoke fixtures: createComponent → ... → removeComponent cycle
The v0.5.1 smoke flow creates its own throwaway folder
(`mcpSmoke51_<unix-ts>`), exercises the new tools on it, then
cleans up via the actual removeComponent (dryRun + final). This
proves the tools work end-to-end and ensures smoke leaves no
debris on the test station. addExtension / linkSlots /
unlinkSlots e2e fixtures need station-specific setup (real
extension types, compatible slot types) — deferred to v0.5.2 with
proper helper functions.

### invokeAction + setSlot share the same coercion logic
Both tools coerce JSON primitives to BSimple BValues based on the
existing/expected slot/parameter type. Identical 6-type dispatch
table (BString/BBoolean/BInteger/BLong/BFloat/BDouble) is
duplicated across `SetSlotTool.coerce()` and
`InvokeActionTool.coerceForActionParam()`. A `BValueCoercer`
helper would dedupe this in v0.5.2 — small refactor, not worth
its own commit during the M1-tail sprint.

### Inline schema-helper duplication for nameStrategy
`AddExtensionTool` re-uses the nameStrategy enum schema from
`CreateComponentTool`. Rather than widening either class's package
surface for a shared helper, inlined the makeNameStrategyParam()
copy with a shimmed name. Same dedupe candidate as the BValueCoercer
above — queued for the v0.5.2 cleanup pass.

## Post-smoke hardening (2026-05-11)

First real-station smoke (4.15.3.28) shook out four issues; 5 fix
commits on top of the branch took it to **33 / 33 green**:

| Commit | Fix |
|---|---|
| `eca9523` | smoke: capture `Mcp-Session-Id` from `initialize()` response on the v0.5/v0.5.1 paths (was discarded → `setupTestUser` HTTP 400). |
| `4c879b7` | smoke: clear stale `client.session_id` before the v0.4.1 `initialize()`; add `setupTestUser` diag fields (`tagsSetReturned` / `readbackHash` / `readbackMatches` / `saltLen`) for the tag-persist investigation. |
| `4612c06` | first ord-fix attempt (`getSlotPathOrd().toString()`) — insufficient: per the baja bytecode `getSlotPathOrd()` is `BOrd.make(getSlotPath())`, still relative. |
| `cadf51c` | **`tools.Ords` helper** — `resolve(s)=BOrd.make(s).get(Sys.getStation())` (relative `slot:/...` → station root; absolute ords ignore the base) and `stationOrd(c)="station:|"+c.getSlotPath()`. Wired into all 7 write tools (parent/sink/target resolution + result ords). |
| `271e8e6` | **`McpProtocol.callTool`** — catch tool-thrown `RpcException` separately and surface `result.errorCode`/`result.errorData` (codes -32013..-32016 were unobservable before). smoke: step 27 creates a `baja:String` prop then `setSlot`s it (a bare `baja:Folder` has no settable scalar slot); step 28 asserts `result.errorCode == -32014`. |

Root causes worth remembering:
- A bare `slot:/...` ord on a station servlet-handler thread resolves
  against the thread's *implicit* base, which is the local host — hence
  the cryptic `ord not resolvable: localhost`. Always resolve write-tool
  ords against `Sys.getStation()`.
- MCP reports tool failures via `isError` content, not JSON-RPC errors —
  so a tool's `RpcException` code is dropped unless explicitly carried on
  the result. We chose a `result.errorCode` extension field.
- `BUser.tags().set(Tag)` *does* persist without a Context on 4.15 — the
  early user-Bearer 401s were entirely the smoke's session-id handling,
  not the tag write.
